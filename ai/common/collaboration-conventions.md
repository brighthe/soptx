# 协作约定（人 ↔ AI）

本文件是 soptx_heliang 仓库人机协作方式的单一事实源（SSOT）。
Claude 与 Codex/agents 均须遵循；`ai/claude/CLAUDE.md` 与 `ai/agents/AGENTS.md`
只留指针，不复写规则。

## 约定一：程序实现按「拆分 → 确认 → 逐步执行」进行

### 触发范围（实现类任务）
动手前须走本约定：
- 新增 / 修改 / 删除源代码、测试、脚本；
- 重构、接口变更、依赖或构建配置改动；
- 多文件或跨模块的成套改动（即便单处改动很小）。

不触发（除非用户要求）：读代码、检索、答疑、单文件局部文档编辑、只读诊断与运行。
边界不清时先问一句，不默认动手。

### 执行协议
1. **先拆分，不先写码**：给出子任务清单，每条含三要素——
   - 目标：一句话、可独立验收；
   - 预期产出：涉及的文件 / 新增对象 / 命令；
   - 验证方式：如何确认这条做对（测试、断言、数值对照、人工检视点）。
   并标出子任务间的依赖与顺序。
2. **等确认再动手**：用户可增删、调序、合并、改验收标准；未确认不进入执行。
3. **逐个执行、逐个交接**：一次只做一个子任务；完成后停下，交代
   「做了什么 / 产出 / 验证结果 / 是否偏离预期」，等用户确认再进下一个。
   **默认不连续执行多个子任务**；用户明确授权「这几条连做」时可批量，
   但须在批次末统一交接。
4. **偏差即停**：执行中若发现拆分不成立、遇预期外阻碍、或需扩大改动范围，
   立即停下说明，重新拆分并请确认，不擅自扩张。

### 目的
让用户全程参与、可**拨动与检视每个中间环节**，而非只接收一个跑完的黑盒结果。
子任务粒度以「用户能看懂、能在此暂停检查」为准。
